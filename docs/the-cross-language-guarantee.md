# The cross-language guarantee

Written for: Ruby developers who build with agentspaces-rb.

`gems/agentspaces/test/golden.json` is a vendored copy of `golden.json` from the [AgentSpaces specification](https://github.com/badmonkeyai/agentspaces-spec), the vectors the Java codec produced (`tools/golden/GoldenVectors.java` in the core repository). For each feature this peer runs, the suite builds the vectors' encodings and signatures and matches them byte for byte (RFC 8032 signing is deterministic). It decodes and re-encodes every CBOR vector to its own bytes, including the vectors of features this peer does not run, such as the WebRTC signalling records and the content swarm's messages, and it refuses every hostile `adv_*` input as Java does. [What Ruby supports](scope.md) lists the features it runs. Refresh the copy with the specification's `sync-golden.sh`; with the specification checked out beside this repository, `rake golden:check` refuses a drift.

The CBOR codec writes and reads the AgentSpaces wire encoding, the image of Java's codec. An `Integer` inside a Java long encodes as a plain integer and any other `Integer` as a tag 2 or 3 bignum, a `BigDecimal` encodes as a normalized tag 4 decimal, a `Float` encodes as a float64, and an `AgentSpaces::CBOR::Float32` encodes as a float32, since Ruby has one `Float` class. An application reads each of these back as the same type, and the value re-encodes to the same bytes, so a Java `BigInteger`, `BigDecimal`, or `float` survives a Ruby read and write. An entry field declared `Float` widens an `Integer` on assignment, which is what a Java `double` component needs. The encoder refuses a map key that is not text, a Hash whose Symbol and String keys name the same text, a NaN or infinite `BigDecimal`, and text that is not valid UTF-8.
