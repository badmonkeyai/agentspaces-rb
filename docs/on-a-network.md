# On a network

Written for: Ruby developers who build with agentspaces-rb.

The peer is strict in what it accepts and cautious in what it sends. It decodes a carrier only in the wire encoding: every head is the shortest, every map is indefinite with unique text keys, every array and byte string is definite, a text past 3996 UTF-16 code units travels in Jackson's chunks and no shorter text is chunked, the only tags are 2, 3, and 4 in the forms Java writes, with a bignum magnitude of at most 1000 bytes as Java's reader keeps it, the only simple values are false, true, and null, a float is a float32 or float64 with Java's one NaN, nesting stops at 64 levels, nothing follows the item, and re-encoding what it decoded gives exactly the bytes received. It then holds each protocol record to its schema (`AgentSpaces::Schema`, generated from Java's serializers): the fields in declared order, no unknown field, null only where Java writes null, and each field in its declared CBOR type, so an epoch as a float, a decimal, or text, a bid as an integer or null, or a byte string where text belongs makes the carrier undecodable. It also refuses what Java's record constructors refuse: a null in any field of an advertisement, card, founding, or envelope except `Envelope.to` and `RevocationAdvertisement.successor`, an entry record with both or neither of `payload` and `payloadRef`, an inline payload past 64 KiB, a key epoch below 1, and an agent certificate with a zero ttl or an encryption key of another length than 32 bytes. A frame that fails counts in `peer.malformed_frames`, and a space delta that fails drops whole and counts in `peer.deltas_undecodable`, while the rest of a pull response still folds. A payload outside the wire encoding leaves its entry replicated, since the signature covers its bytes, and every read skips its value. A stamp is the canonical text `<physical>:<logical>:<node>`: digits with no leading zero, sign, fraction, or exponent, a physical part within a signed 64-bit integer, and a node with no colon, no control character, and no lone surrogate, carried as a definite-length, untagged CBOR text in shortest-form UTF-8, so the bytes a signer signed always equal the stamp's re-encoding. A frame whose stamp is any other CBOR item, the same text under a longer length header or as an indefinite-length text of 3996 UTF-16 code units or fewer included, does not decode and counts in `peer.malformed_frames`. A stamp holds at most 3996 UTF-16 code units, since a longer text travels only in Jackson's chunks, and the clock refuses a node past 3965 units, so the peer reads no chunked text as a stamp and issues none. The capability clients read their pipe payloads under the same schema checks. An agent id is `<peerId>/<localName>` with no `/` and no `:` in the local name, as Java's `AgentId` reads it on the wire, and `Identity#agent` also refuses a control character, since an agent id is the node of every stamp its agent signs. The peer verifies a claim's signature over the claim as it arrived, a `TakeClaim` in record order, and orders bids as Java's `Double.compare` orders them, so a bid of -0.0 ranks ahead of a bid of 0.0. A state's signature covers its dots sorted by replica in UTF-16 code unit order, as Java sorts them. Every verified frame then passes a `FrameFilter`, which judges its stamp in the order of SPEC §9 and counts each drop under the name of Java's `PeerNode` counter: a stale stamp older than five minutes (`peer.frames.stale`), a sender-and-stamp pair it has seen (`.replayed`), a stamp past the HLC drift bound by at most the five-second skew margin (`.far_future_skewed`) or further (`.far_future`), and a logical counter above 65536 (`Wire::HLC_LOGICAL_LIMIT`, `.logical_refused`), each without a reply. The peer orders or merges only stamps the strict parser `Wire.hlc_parse` accepts, comparing nodes and holders by UTF-16 code units as Java does. The peer checks a folded state or claim in this order: its signatures and certificate, its actor's revocation, then its stamps, so a revoked actor counts in no stamp counter. It refuses a record, lease stamp, `signedAt`, or claim stamp whose logical counter lies above the limit and counts it in `peer.stamps_logical_refused`, and it refuses a record, lease, or claim stamp that lies more than an hour past the drift bound and skew margin and counts it in `peer.stamps_far_future_refused`, each once per distinct signed content. A state or claim stamped within that hour waits and counts once in `peer.stamps_far_future_deferred`, and the peer judges every later offer afresh, so it merges a waiting or refused offer once its wall clock catches up. An agent certificate bounds a record or claim by its own validity window alone, so an agent-signed stamp meets these same rules. An agent-signed state's `signedAt` meets the same rule as its record and lease stamps: it merges up to the drift bound and skew margin, waits as deferred for up to an hour past that, and is refused beyond. A claim on an entry the peer never held leaves the claim map once its expiry passes, so claims for unknown entries cannot grow the map without bound. The local clock carries into the next millisecond at the limit and clamps a remote stamp one millisecond inside the drift bound, so one hostile stamp cannot freeze the clock, a lease, or a take, and a carry never pushes an honest peer past a receiver's drift check. The clock and `Identity#agent` refuse a node the stamp grammar does not admit, so the peer never signs a stamp a receiver cannot decode. A kind the peer does not speak counts in `peer.ignored_kinds`, a body that does not decode in `peer.malformed_frames`, and the reader goes on. A lost connection is a hiccup: the peer re-dials its seeds, failing over across them, and pauses after each round of refusals by one redial table shared with the core and every client: 5, 10, 20, then 30 seconds, then 5 seconds again, each spread by up to 10 % either way so peers do not redial in lockstep, until `close` (swarm retries, ROBUSTNESS.md 10.3 E5). Only two things start the table again: the end of a link that held for at least 5 seconds (`reconnect_interval`), and a wake from sleep. `connect_any`, `bootstrap`, and each round of re-dials dial the seeds in list order, 250 ms apart, and a refusal starts the next dial at once (RFC 8305, "Happy Eyeballs"). The first to answer wins, the seeds not yet dialled are not dialled, and a connection that answers later is closed (`peer.seed_dials`, `peer.late_seed_channels`). So a first seed that answers keeps its place, and a silent one costs 250 ms, never a connect timeout. Each dial gives up after 10 seconds, the TLS handshake included, so a seed that accepts the connection but never answers the handshake holds no dial for longer. After a lost link the round dials the other seeds in list order and the seed just lost last. A link that ends within `reconnect_interval` of its dial counts as a refused round and waits the next step, so a seed that accepts each dial and drops it at once gets the same pauses (10.6). A link the peer has read nothing from for 45 seconds, 1.5 times the 30-second keepalive bound, is asked with a PING to the seed; if nothing comes back within the 2-second ping timeout the link is closed (bytes of a frame still arriving, of any size, count as an answer) and the peer fails over to the next seed, rather than waiting minutes for TCP to give up on a seed that vanished without a word (`peer.links_silent`; each PING to the seed counts in `peer.seed_pings`). A wake from sleep (`peer.resumes`) while the link is up sends the seed a PING at once under the same rule (`peer.wake_pings`), so a seed that does not answer within 2 seconds is failed over at once, and the peer re-introduces itself on a link that answers. A wake with no link, during a pause between rounds, dials at once. The peer answers its seed's text digest of a space with the states and claims the seed lacks, so its own write whose rumor was lost on the link reaches the group at the seed's next anti-entropy round. Another member's text digest, relayed by the seed or not, draws an answer only for the spaces where the peer holds a claim made here that a better claim of another member displaced, with or without its completion, and carries only those entries (another completion of its own work draws nothing, as in the core), at most 16 at once and 4 a second per asker (`peer.displaced_digest_answers`, `peer.relayed_answers_paced`); any other is ignored. So a winner's targeted round reaches a displaced Ruby holder too. While one of its takes holds an entry and its claim displaced another holder's, the peer sends that holder an anti-entropy round of its own, a text digest of the space addressed to it through the seed, at once and then after 1, 2, 4, 8, and 16 seconds, at most six, so the displaced holder's completion reaches it even though the seed holding the better claim drops it (`peer.displaced_pull_rounds`). On every wake and every wall step the peer judges each take it holds at once. A take has lapsed when its claim is no longer its own or its lease has ended, most often while the machine slept: it is no longer renewed, `Lease.keepalive` stops at once, and its `complete` raises without completing anything or writing the result, which is late and counted once (`peer.late_takes`; the takes a wake found lapsed count in `peer.held_takes_lapsed`). A loop that wakes more than 30 seconds late with no wall step, a process that was frozen, is a wake too (`loop_stats[:late_wakes]`). After a wake the peer also re-pulls the membership view from its seed, leaving out the cards that lapsed, and keeps each member whose card lapsed only during the absence in its view until the seed answers or 11.25 seconds pass (`peer.view_reprobes`), so a member is probed before it is dropped. The peer then re-introduces itself and re-pulls revocations, advertisements, and spaces. `close` by the owner is final.

Cards follow SPEC v0.1.32 (AppCard origin and formats, 2026-11-09). The peer reads the v0.1.32 `AppCard` and `AgentCard` schemas and advertises `wire.appcard=2`; `Peer.new(..., appcard_level: 1)` advertises nothing, so a test can build a mixed fleet. It refuses at decode what Java's card records refuse: an AppCard `kind` outside `peer`, `fed`, `gateway`, and `assembled` (a static app assembled from extracted data, which reads nothing live), a `host.signOn` outside `idp` and `none`, an `origin` or `formats` that breaks its grammar or bounds (lengths in UTF-16 code units), a component `role` outside `panel`, `control`, and `row`, and a stub whose `spill` breaks the spill rules. `publish_ad` raises `Schema::Error` on a card these rules refuse, so an old writer's card of kind `realm` or `signOn` `tenant` never goes out. A dial-only peer cannot see every member's hints, so `publish_ad` issues no gated field: it leaves out an AppCard's `origin`, `formats`, and a host whose `signOn` is `idp`, and counts each such card in `peer.app_cards_downgraded`. The peer runs no content swarm, so it never spills a card. A card past 65,536 bytes travels inline in full and counts in `peer.cards_oversize_inline`, and a card past 57,344 bytes logs a warning once per id and size. `peer.resolve(card)` returns a card without `spill` as it stands and completes a stub from its parts document through `peer.spill_store`, an object whose `get(root, size)` returns the document's bytes. The peer runs no content swarm whose piece check would refuse other bytes, so `resolve` checks the document's content root against `spill.root` itself. A document of another length or another content root, one that does not decode as the kind's parts record, or one whose non-empty fields differ from `spill.parts` raises `Peer::ResolveError` and counts in `peer.spills_refused`; a `size` above `spill_max_fetch_bytes:` (16 MiB by default) fails before any fetch and counts in `peer.spills_over_limit`; with no store attached, `resolve` raises `Peer::ResolveError` at once. No failure touches the cached stub. Remote actions, and so the RubyLLM and MCP tools, resolve each stub first and leave out a card they cannot resolve. The advertisement cache holds at most `ad_cache_max_entries:` (8,192) advertisements and `ad_cache_max_bytes:` (32 MiB) of their encodings: after the expired entries leave, it refuses a new id that would pass either bound and a newer version that would pass the byte budget, keeps what it holds, and counts each refusal in `peer.ads_refused_cache_full`. An older or equal version leaves the held one in place and counts nothing, as Java's `AdCache` does. `AgentSpaces::Cards` holds the card constants and `card_parts`, `card_stub`, and `card_complete`.

- **TLS.** A `tls://host:port` seed dials TLS 1.3 and presents a channel certificate: a fresh P-256 key in a certificate the peer's Ed25519 identity key signs, with the identity key in the CN (SPEC §5.6). The peer attests the remote end the same way and refuses one that attests nobody. On an attested connection it announces `CHANNEL_HELLO`, so a Java node stops signing every frame toward it, and it accepts the bare frames that follow from exactly the attested sender. Tested against a Java seed with `requireAttestation(true)`.
- **WebSocket and HTTP.** A `ws://` or `wss://` seed dials RFC 6455 with the `aspace.1` subprotocol (default path `/aspace`); an `http://` or `https://` seed runs the specification's long-poll exchange (default path `/aspace/h`), for networks that pass only HTTP. `wss` and `https` attest a listener that presents an endorsed channel certificate, or trust the system roots and check the host name.
- **Session attestation.** On a connection the transport cannot attest (`tcp`, `ws`, `http`), the peer exchanges one fully signed `SESSION_HELLO` each way with a member that advertises `wire.session=1`, derives a key over X25519 and HKDF, and from then on tags its frames with HMAC-SHA-256 in place of an Ed25519 signature.
- **Plain transports.** A `tcp`, `ws`, or `http` seed to a non-loopback host is refused unless the configuration sets `allow_plain: true`, because `dev-local` signs every frame and encrypts nothing.
- **Forks.** A peer records the pid that started it. A forked child closes the connections it inherited without a word to the remote, and any use of an inherited peer raises `AgentSpaces::ForkError`, naming `AgentSpaces.after_fork`.
- **Keys.** `Identity.load_or_create(dir)` writes `peer.key` (PKCS#8 DER, owner-only, atomic rename) and `peer.pub`, the layout a Java peer reads, and refuses a key file others can read. `inspect`, `to_s`, and `pp` of an identity print its PeerID and nothing secret.
